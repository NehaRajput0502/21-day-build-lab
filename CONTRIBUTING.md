# Add your own one-file project

This lab is open to everyone. If you can build something small, useful or fun in **one HTML file**,
it can go live here next to the original 21 days, with your name on it.

Live site: https://neharajput0502.github.io/21-day-build-lab/

## The rules

1. **One file.** Your project is a single `index.html`, with its CSS in one `<style>` block and its
   JavaScript in one `<script>` block.
2. **No outside code.** No CDNs, frameworks, trackers, ads, analytics or external fonts. It must work
   offline when someone double-clicks the file.
3. **It works.** Open it in a desktop browser and on your phone before you send it. No console errors.
4. **It's yours.** Write it yourself. AI tools are fine for help, but only send code you have tested
   and understand. If you borrow a snippet, credit it in a comment and make sure its licence allows it.
5. **It's useful or fun.** A real tool, game, animation or generator. Copies of the 21 existing days,
   "hello world" pages and name-only changes won't be merged.
6. **It's safe for everyone.** Nothing offensive, nothing that collects personal data, nothing that
   sends data anywhere.
7. **One project per pull request.**

By sending a pull request, you agree that your project is released under this repo's
[MIT License](LICENSE).

## Where your project goes

    community/<your-github-username>/<project-name>/index.html

For example: `community/riya-codes/tip-calculator/index.html`

Use lowercase letters, numbers and hyphens in folder names. Only add your own folder and don't edit
other files. Your project is added to the site's community list after it is merged.

## How to send it (no Git needed, all in the browser)

1. Start from [`community/TEMPLATE.html`](community/TEMPLATE.html) and build your project inside it.
2. On this repo, click **Fork** (top right), then **Create fork**.
3. In your fork, click **+** and choose **Create new file**.
4. In the file name box, type `community/your-username/your-project/index.html`.
   Each `/` you type creates a folder.
5. Paste your code, then click **Commit changes**.
6. Go back to your fork's main page, click **Contribute**, then **Open pull request**.
   Fill in the checklist and click **Create pull request**.

Every pull request is reviewed. If something needs a fix, you'll get a comment; update the file in
your fork and the pull request updates by itself.

## Other ways to help

Look for [issues labelled `good first issue`](https://github.com/NehaRajput0502/21-day-build-lab/labels/good%20first%20issue): bug fixes, mobile
layout, accessibility and small features for the 21 projects. The same rules apply: one focused change
per pull request.

## Be kind

Be respectful in issues and reviews. Everyone here is learning.
